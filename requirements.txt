AXIS DEPLOY — steps

1. Supabase → SQL Editor → paste setup.sql → Run.
   (skip if you already ran it for 3.zip or 4.zip)
2. Deploy to Vercel.
3. What changed in this build (18.zip) — ARNOLD ROTATION + TASK GROUPS:
   - Bot now knows your split rotation (fixed order, your exercises from
     SPLIT_MAP): SHOULDERS+ARMS → CHEST+BACK → LEGS.
     /log asks "which day are you on?" ONCE (3 buttons), then the day
     auto-advances after every logged session. Rest days burn nothing —
     the day flips only when you train. /splitday re-picks anytime,
     /split shows TODAY/NEXT. Logging any non-Arnold session leaves the
     rotation untouched.
   - POINTS BUG FIXED: every task silently maxed at 1pt because the
     "Effective points" draft reset to 1 after each commit. The override
     input is gone entirely — points are now always the auto value.
   - ADD-TASK FORM SIMPLIFIED: Impact + Resistance only (Depth select and
     the manual points input removed). New Group picker:
     COLLEGE / BODY / MIND / MUSIC / DESIGN (or Inbox).
   - New TASK GROUPS section on the Core page: every task you ever made,
     bucketed by group, open first then done (dimmed), with day keys.
   - SCHEMA: run setup.sql — adds core_todos.tag + commander_profile
     .split_day. Code degrades gracefully if not run yet (tags go null,
     bot keeps asking the day), but run it.

   (17.zip) — TELEGRAM BRIDGE FAULT LOCK (the
   "600 SYSTEM BRIDGE FAULT messages" fix):
   - ROOT CAUSE: you sent a random file, the bot tried to feed ANY document
     to Groq voice transcription, it faulted, the webhook answered HTTP 500,
     and Telegram re-delivered the same update for up to 24h — each retry
     sent another fault message. No dedupe existed. One file = a storm.
   - FIXED x3:
     1) Webhook now ALWAYS answers 200, faults included.
     2) update_ids are remembered 24h — a re-delivered update is ignored,
        never re-processed.
     3) Only genuine audio (voice/audio, or documents with an audio
        mime/extension, ≤20MB) ever reaches transcription. Random files
        get one polite "send text or a voice note" reply. Network calls
        in the voice path now have hard timeouts too.
   - After deploy, Telegram may deliver 1–2 leftover fault messages from
     the old storm, then it stops for good. To wipe the pending queue
     instantly: re-register the webhook with
     &drop_pending_updates=true (step in chat).
   (12.zip) — NUTRITION GOES MFP-FIRST:
   - Manual food logger is OFF the page (textarea, templates, iOS
     shortcut card all retired). MFP is the data source now: log meals
     in the MFP app, tap "Sync from MFP now" here.
   - TODAY SUMMARY moved to the very top of the page.
   - HYDRATION now syncs from MFP too (reads your MFP water, shows a
     MEASURED // MFP badge; tap-cartridges still work and override
     until the next sync).
   - Sync is now IDEMPOTENT: re-tapping replaces that day's MFP rows
     instead of duplicating them.
   - The MFP SOURCE card shows CREDS SET / MISSING and CRON ON/OFF so
     you can see config problems before tapping sync.
   - BUG FIXED: the nightly Vercel cron was only hitting the health
     check and never actually syncing. It now syncs the day that just
     ended — but only after you add a CRON_SECRET env var in Vercel
     (any random string). Without it the cron stays inert on purpose.
   - Old apple_health rows are untouched; use CLEAR if you want them gone.
   (13.zip: result line always reports water status + user_id param.)
   (16.zip: Telegram nutrition route PUT TO SLEEP — your call. /eat, /food,
   'ate ...' and the Nutrition menu button now reply 'moved to MyFitnessPal'
   and write NOTHING. Workout (/log, shorthand, voice) and tasks (/done)
   unchanged. One bot, one token — same as always.)
   (15.zip: DESK/SUMMER/FIELD SYSTEM KILLED — your call. No mode picker on
   tasks, no Primary-focus card; scoring is one flat work pool (same
   caps: low-tier max 10, no-hard gate 25, work cap 40, same grade
   thresholds). Bottom line: numbers can only stay equal or rise a hair
   vs the old mode logic — never silently drop. Core hero is now a
   NEXT UP queue (3 hardest open tasks, tick them done right there).
   Must-win chip moved into the score card. One schema line added to
   setup.sql (work_points_v4) — run it once. Old mode columns are left
   untouched with your history.)
   (14.zip: HUD bar truly sticks while pages scroll — body no longer a
   scroll container; Config page grouped with an ADVANCED fold; MFP sync
   taps now run in the background with a pulsing chip; page-switch
   transitions + press feedback, all native CSS, no libraries.)
   (13.zip adds: the sync result line now ALWAYS reports water status —
   applied / not-logged-in-MFP / exact failure reason — and the water
   request sends the documented user_id param as well as the header.)
   - Everything from 11.zip still included (MFP mobile-app OAuth login).
   IMPORTANT if your MFP is a Google sign-in account: it has no MFP
   password. Add one: myfitnesspal.com → log out → Forgot password.
   Then set MFP_USERNAME (your email) + MFP_PASSWORD in Vercel env and
   redeploy. Google sign-in keeps working too.
4. If sync ever looks stale: hard-refresh once (Ctrl+Shift+R).
